# FurkVPN для iOS

iPhone- и iPad-клиент FurkVPN (iOS 15+): SwiftUI-приложение и расширение Packet Tunnel с тем же ядром
Xray-core и той же Go-обёрткой (`core/libxray`), что в Android-приложении ([furkvpn-android](https://github.com/foxodever/furkvpn-android)).

```
FurkVPN/      приложение: экраны (Views/), подписка и API (Http.swift), VPN-профиль (VPNController.swift),
              команды для «Быстрых команд» и Siri (Intents.swift), демо-данные для скриншотов (Demo.swift)
FurkTunnel/   расширение Packet Tunnel: ядро Xray на utun-дескрипторе туннеля
Shared/       общее для обоих: модели, хранилище в App Group, обёртка над ядром (Core.swift), сообщения
project.yml   описание проекта для XcodeGen (FurkVPN.xcodeproj в git не хранится)
build.sh      сборка на macOS: ядро → Frameworks/Libxray.xcframework, проект, IPA
screenshots.sh  скриншоты в симуляторе (демо-сборка)
```

## Как это работает

- Ключ, подписка, зеркала, `x-hwid` и прочие заголовки, API furkapp.net — как в Android (см. [README Android-приложения](https://github.com/foxodever/furkvpn-android#readme)).
  `x-device-os: iOS`, модель — вида `iPhone15,3`. HWID хранится в связке ключей «только на этом устройстве»:
  переустановка приложения — то же устройство, новый iPhone из резервной копии — новое.
- Разбор ключа и подписки, правила маршрутизации и сборка конфига туннеля написаны на Go
  (`core/libxray/keys.go`, `subscription.go`, `routes.go`, `tunconfig.go`) — это перенос Kotlin-кода
  Android-приложения вместе с его тестами. Swift только показывает экраны и управляет VPN.
- Приложение складывает подписку (`subscription.json`, `subscription_configs.json`) и настройки в общий
  контейнер App Group `group.com.furkvpn.app`. Расширение при запуске берёт оттуда выбранный сервер и правила,
  собирает конфиг (`BuildTunnelConfig`: вход TUN, DNS через модуль Xray по TCP, свои правила перед правилами
  сервера) и запускает ядро на utun-дескрипторе туннеля (`StartTunnel`).
- **Соединения ядра привязаны к сети телефона**: расширение узнаёт физический интерфейс (`en0`/`pdp_ip0`,
  NWPathMonitor) до запуска ядра, и `BuildTunnelConfig` с `interface` ставит `sockopt.interface` всем исходящим и
  `autoOutboundsInterface` TUN-входу (на Apple — `IP_BOUND_IF`). Без этого на iPhone соединения ядра к серверам
  уходили в его же туннель (петля): VPN «подключён», трафика нет, расширение не отвечает (1.1.1–1.1.4). Смена
  интерфейса (Wi-Fi ↔ сотовая) перезапускает ядро уже с новым. Интерфейс — `Core.physicalInterfaces`: сначала те,
  через которые идёт путь, и только с адресом (`UsableInterfaces`): включённый, но никуда не подключённый Wi-Fi
  iOS тоже перечисляет, а сокет, привязанный к нему, получает «network is unreachable» (1.1.8 на сотовой
  привязывался к `en0`). Перед запуском ядра и после смены сети `ProbeNetwork` спрашивает DNS 77.88.8.8 без
  привязки и через каждый интерфейс сразу: ядро привязывается к первому, через который ответ пришёл, без
  привязки — если прошёл только такой запрос. В режиме отладки та же проверка идёт ещё и до настроек туннеля,
  а в отчёт попадают путь по iOS (статус, причина, интерфейсы) и адреса интерфейсов. 1.1.9 на телефоне: до
  туннеля сеть у расширения есть, после `setTunnelNetworkSettings` путь `unsatisfied (notAvailable)` и любой
  сокет расширения, даже привязанный к `pdp_ip0`, — «network is unreachable»: iOS не выпускает провайдера мимо
  его туннеля. Поэтому в режиме отладки с туннелем пробуются и другие пути: `NWConnection` (как есть и с
  `requiredInterface`), `createTCPConnection` из NetworkExtension и сокет к 77.88.8.1, который в этом режиме в
  `excludedRoutes`. «Диагностика VPN» показывает подписи приложения и расширения (ID подписи, команда,
  application-identifier, networkextension, App Group — `SignatureInfo` читает их из Mach-O) и
  embedded.mobileprovision обоих: по ним iOS сопоставляет расширение с приложением.
- Туннель: 172.19.0.1/30 и fdfe:dcba:9876::1/126, DNS 172.19.0.2 — как в Android. Маршруты — всё адресное
  пространство, а при «Локальная сеть напрямую» (включено по умолчанию) — без домашних сетей, link-local и
  multicast (`TunnelRoutes`, перенос `TunRoutes` из Android 1.7.1: 39 префиксов IPv4), плюс 172.19.0.2/32:
  AirPlay, Chromecast и принтеры находятся как без VPN. Переключатель при подключённом VPN меняет маршруты
  туннеля (новые настройки сети и перезапуск ядра). Соединения самого расширения идут мимо туннеля.
- **Переподписанные IPA** (сервисы и утилиты подписи часто меняют bundle id и App Group под свой
  сертификат): ID расширения туннеля приложение берёт из своего бандла (`TunnelExtension`), App Group — наша
  или `group.<id приложения>`, если подписчик сделал такую (`Store.groupId`). Конфиг выбранного сервера и
  правила (`TunnelPayload`) приложение передаёт при запуске (`startVPNTunnel(options:)`), в `reload` и в пинге,
  и сохраняет в профиле VPN (`providerConfiguration`) для запусков без приложения — расширению общие файлы не
  нужны. Ошибка запуска или неожиданного отключения приходит в приложение через `fetchLastDisconnectError`
  (iOS 16+). Настройки →
  «Диагностика VPN» показывает ID приложения, расширения и профиля, App Group и последнюю ошибку.
- Смена сервера или правил при подключённом VPN не переподключает VPN: приложение шлёт расширению `reload`,
  и оно перезапускает ядро на том же туннеле. Смена во время подключения отправляется, как только VPN
  подключится (запуск мог прочитать прежний сервер).
- Подписка: добавление ключа и обновления идут по очереди (обновление не перетирает новый ключ, при запуске
  нет двойной загрузки); ключ с доменом, которого больше нет в `allowedSubscriptionHosts`, — ошибка. Конфиги
  серверов сохраняются с `fetchedAt` своего списка: расширение не возьмёт конфиг из другой загрузки.
- **Пинг** всегда в приложении (`PingVia`). При включённом VPN соединения проверки привязаны к сети телефона
  (`sockopt.interface` = `en0`/`pdp_ip0` из `PhysicalNetwork`, на Apple — `IP_BOUND_IF`): iOS не загоняет
  такие сокеты в туннель, и пинг меряет путь до сервера, а не через текущий. В расширении пинговать нельзя:
  каждая проверка — отдельное ядро Xray, проверка «Автовыбора» сразу стучится во все его 15–20 серверов, а их
  соединения живут до таймаутов — «пинг всех» в 1.1.1 выходил за ~50 МБ, iOS убивала расширение и VPN
  отключался. Как в Android 1.6.2: кнопка пинга не блокируется, повторное нажатие начинает заново; удержание
  сервера, который ждёт в очереди «пинговать все», проверяет его сразу; не больше 6 проверок. Расширение
  держит только рабочее ядро (`SetMemoryLimit(32, 50)` — Go собирает мусор раньше лимита).
- **Автовыбор** — то же, что в Android-сервисе: новое ядро при смене сети (Wi-Fi ↔ мобильная), раз в 10 секунд
  `AutoSelectCheck` смотрит проверки балансировщика и перезапускает ядро (не чаще раза в 2 минуты), если умерли
  серверы, через которые шёл трафик; после сна дольше 5 минут серверы перепроверяются сразу; после перезапуска
  запасным ставится сервер, который был лучшим.
- Ссылки `furkvpn://import?url=…` (их открывает furkapp.net/import на iPhone) добавляют ключ.
- **QR-сканер** (экран приветствия) — ключ с QR-кода камерой или с фото из галереи.
- **Телевизор** (Настройки → «Подключить телевизор», если есть камера): QR-код с экрана FurkVPN на Android TV
  (`https://furkapp.net/tv/<код>`, `TvCodeFromLink`) после подтверждения отправляет ключ этого телефона в
  `POST /api/v1/tv/send`. Ссылки `furkvpn://tv/<код>` — то же.
- **Быстрые команды и Siri** (iOS 16+, `Intents.swift`): «Подключить VPN», «Отключить VPN», «Включить или
  выключить VPN» — без открытия приложения; подходят для автоматизаций и кнопки действия. Профиль VPN
  создаётся первым подключением в приложении (там iOS спрашивает разрешение).
- **Liquid Glass** на iOS 26 (сборка Xcode 26 — workflow выбирает его, если он есть на машине): кнопка
  подключения, выбор сервера, кнопки сайта/бота/поддержки, вкладки серверов, сообщения и кнопки экрана
  приветствия — стекло поверх фона с мягким свечением фирменного цвета; карточки с текстом (тариф, объявление)
  остаются сплошными. На iOS 15–18 — прежний плоский вид (`Views/Glass.swift`: всё стеклянное за
  `#if compiler(>=6.2)` и `#available(iOS 26.0, *)`). Список серверов — шторка на полэкрана (iOS 16+).
- В настройках — политика конфиденциальности и пользовательское соглашение (`site.domain`/privacy, /terms);
  «Войти через сайт» сразу открывает личный кабинет.

Чего нет по сравнению с Android: приложений без VPN (iOS не даёт VPN-приложению выбирать приложения),
раздачи интернета, журнала подключений, определения белых списков, импорта и экспорта настроек, двух панелей
на широком экране (на iPad — одна колонка по центру).

## Ядро

`core/` — копия Go-обёртки над Xray-core из [furkvpn-android](https://github.com/foxodever/furkvpn-android) (там она собирается в `libxray.aar`)
плюс то, что нужно только iOS: разбор ключа и подписки, правила, сборка конфига туннеля (`keys.go`,
`subscription.go`, `routes.go`, `tunconfig.go`), маршруты туннеля (`tunroutes.go`), код телевизора (`tv.go`)
и вызовы для Swift (`apple.go`). Это перенос Kotlin-кода Android-приложения: его изменения (KeyParser,
SubscriptionParser, RouteRules, XrayConfigBuilder, TunRoutes, TvPairing) нужно переносить сюда вместе с тестами;
перенесено всё по Android 1.9.1. Общие файлы (пинг, `pin.go`,
`dnsfix.go`, `hysteria.go`, версия Xray в `go.mod`) правятся в обоих репозиториях: исправление в одном нужно
перенести в другой. Отделено от Android-репозитория 2026-11-02 (ветка `ios`, коммит 92632d7) вместе с историей
iOS и ядра.

## Сборка

Нужны macOS с Xcode, Go (версия из `core/go.mod`), gomobile и XcodeGen:

```bash
cd core && go install golang.org/x/mobile/cmd/gomobile golang.org/x/mobile/cmd/gobind && gomobile init
brew install xcodegen
./build.sh                    # → build/FurkVPN-<версия>-unsigned.ipa
```

Без Mac собирает GitHub Actions (`.github/workflows/ios.yml`) при пуше в `main`: IPA и конец журнала
сборки кладутся в ветку `ios-build` (её можно забрать ключом деплоя) и в артефакты запуска; `xcode.txt` там же —
какие Xcode были на машине и каким собрано.

**Скриншоты без iPhone**: если в сообщении коммита есть `[shots]`, workflow после IPA запускает
`screenshots.sh` — демо-сборку (флаг `DEMO`, `Demo.swift`: примерные серверы, тариф и «подключено»; в IPA её
нет) в симуляторе на iPhone SE, iPhone Pro, Pro Max, iPad Pro и складном iPhone, если он есть в симуляторе, в
тёмной и светлой теме: приветствие, главный экран, подключено, серверы, настройки → `shots/` в `ios-build`.
VPN в симуляторе не работает (там нет Network Extension) — только интерфейс. Фреймворк ядра собирается и для
симулятора (`iossimulator/arm64`).

**IPA без подписи.** Она подписана ad-hoc с нужными правами (Network Extension, App Group). Поставить её как есть
можно через TrollStore; иначе её нужно переподписать сертификатом разработчика с профилями для
`com.furkvpn.app` и `com.furkvpn.app.tunnel`, в которых есть Network Extensions (Packet Tunnel) и App Group
`group.com.furkvpn.app`. VPN-расширение работает только с платным аккаунтом Apple Developer.
